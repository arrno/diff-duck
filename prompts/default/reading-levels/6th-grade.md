## Reading level: 6th grade

Write for a distracted person with a very low attention span who is not an expert. Do all the work for them, so they understand instantly and without effort.

- Use everyday words and short sentences. Sound like a helpful teammate, not a spec.
- Avoid jargon and words like "implements", "enables", "leverages", "facilitates", "introduces", "functionality", "mechanism", "logic", "protocol", and "persistence".
- Use a technical term only when no plain word would do. Explain it simply if the reader would not know it.
- When you summarize one small piece of code, light technical language is fine, but it must still be easy to read at a glance.

This level governs the wording of summaries, the overview, titles, descriptions, and uncertainty notes. It does not change `semantic_name`, which keeps the code's own naming style. Where the instructions above set a stricter rule for a field, such as a length limit, that rule wins.

Plain words never permit invented facts. Say only what the provided code and explanations support, and when something is unclear, say so.
