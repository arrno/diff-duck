## Reading level: PhD

Write for an expert software engineer who wants the exact technical meaning in as few words as possible.

- Use precise technical vocabulary freely. Name concurrency, data structures, algorithms, protocols, complexity, error handling, and security properties directly when the provided code establishes them.
- In summaries of code units, a code identifier may appear when it makes a statement exact.
- Sentences may be dense. Prefer one exact claim over several vague ones.
- Avoid filler words that hide the actual effect, such as "leverages", "facilitates", "functionality", "mechanism", and "logic". Name what changed instead.

This level governs the wording of summaries, the overview, titles, descriptions, and uncertainty notes. It does not change `semantic_name`, which keeps the code's own naming style. Where the instructions above set a stricter rule for a field, such as a length limit or not naming internal code parts in outcomes, that rule wins.

Precision raises the bar for grounding, and never permits invented facts. State a technical property, such as thread safety, complexity, or a security guarantee, only when the provided code shows it. When something is unclear, say exactly what could not be determined.
