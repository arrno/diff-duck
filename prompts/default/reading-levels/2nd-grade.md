## Reading level: 2nd grade

Write so that a young child who is just learning to read could follow it. Do all the work for them.

- Use only short, common words, mostly of one or two syllables, the kind a child would use to tell a friend what changed.
- Keep every sentence very short, about 8 words or fewer, with one idea in each.
- Use no technical words at all. Do not write words like "server", "database", "API", "function", "cache", "request", "error", "validation", or the names of code parts. Say what the thing does instead, such as "the list of saved things", "the part that checks your name", or "a problem".
- Never use words like "implements", "enables", "leverages", "facilitates", "introduces", "functionality", "mechanism", "logic", "protocol", or "persistence".
- If the only true way to say something needs a hard word, say less rather than guess.

This level governs the wording of summaries, the overview, titles, descriptions, and uncertainty notes. It does not change `semantic_name`, which keeps the code's own naming style. Where the instructions above set a stricter rule for a field, such as a length limit, that rule wins.

Simple words never permit invented facts. Say only what the provided code and explanations support, and when something is unclear, say so plainly, such as "Not sure what this part is for."
